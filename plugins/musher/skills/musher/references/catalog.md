# The Catalog

The Catalog holds open-source apps that are ready to deploy (`BLUEPRINT` listings) and the parts a blueprint can use
(`COMPONENT` listings). Every read on this page is anonymous.

## Finding an app

- **By name:** `GET https://api.musher.dev/v1/catalog/listings:bySlug?slug=<slug>`. Slugs are in the index below.
  A `404` means no published listing has that slug.
- **By description:** `GET https://api.musher.dev/v1/catalog/listings:search?q=<text>`, a case-insensitive match on
  the title and tagline. You can narrow it with `item_type=BLUEPRINT`, `category=…` or `requires_gpu=false`.
- **Everything:** `GET https://api.musher.dev/v1/catalog/listings?limit=100`, paged with `meta.nextCursor`.

The index below is a snapshot. Always confirm against the live API: a listing can be added, deprecated or withdrawn
at any time.

Some apps the user names are listed under another slug:

- Ollama is `ollama` (Ollama + Open WebUI).
- OpenHands is `openhands-agent-canvas`.
- Open WebUI on its own is `open-webui`; with its supporting services it's `open-webui-stack`; in front of vLLM on
  the user's own GPU it's `open-webui-vllm`.
- LiteLLM is `litellm`, and `litellm-stack` adds its supporting services.

If an app isn't in the Catalog, offer to deploy its container image as the user's own app (`deploy-own-app.md`).

With Musher's MCP tools, every step on this page is a tool: `mcp.md`, "Deploy a Catalog app, in order".

## Before you deploy

From the listing, keep `id`, `itemType`, `blueprintId` and `blueprintVersion`.

1. **Only a `BLUEPRINT` listing deploys on its own.** A `COMPONENT` listing (`postgres`, `redis`, `pgvector`, `valkey`,
   …) is a part for a blueprint: `blueprints.md`.
2. **Cost:** `GET /v1/catalog/listings/{id}/cost-estimate` returns `hourlyRate` and `estimatedMonthlyRate` in
   `currency`, for one replica of every node, compute only. `rateStatus: PLACEHOLDER` means launch rates that may
   change. Tell the user the figure, and that storage is billed separately, before you deploy.
3. **Parameters:** `GET /v1/blueprints/{blueprintId}/versions/{blueprintVersion}/deploy-form` (needs the key).
   Generated credentials are filled in at deploy time. Ask the user only for required fields that have no default. The
   listing's `requiredParameterCount` tells you up front whether there are any.

## Deploying

```bash
printf 'Authorization: Bearer %s\n' "$MUSHER_API_KEY" | curl -fsS -X POST -H @- \
  "https://api.musher.dev/v1/organizations/$ORG_ID/deployments:cloneFromListing" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{"listingId": "<id>", "name": "<name>", "parameters": {}}'
```

- `name` is 2 to 63 characters: lowercase letters, digits and hyphens, starting with a letter and not ending with a
  hyphen.
- Optional fields: `parameters`, `replicas` (default 1), `environmentId`, and `connections`, for apps that take a
  model provider: `{"<parameter>": {"external": {"baseURL": "https://…", "apiKey": "…", "model": "…",
  "protocol": "…"}}}`. Never put the user's provider key in the chat; ask them to set it, or use a connection they
  have already made in the Console.
- **Responses:**
  - `201`: the deployment, already in `PROVISIONING`.
  - `402`: not enough balance.
  - `409`: the name is taken, or the listing isn't deployable.
  - `422`: `errors` lists every problem, and nothing is created.
- Then wait for `ACTIVE` and `READY`, and get the URL (SKILL.md, step 5).

**In the Console**, the same deploy is **Catalog → Blueprints →** the app's card **→ Deploy &lt;Name&gt;**, then
Configure, Review and Deploy. Offer it when the user would rather deploy the app themselves.
